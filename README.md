# AES-128 加解密与输出背压

题目取材于一次 AES-128 RTL 生成与综合验证实验。实验中曾出现 RTL 仿真通过、综合网表密文恒为零的故障。修复输出多驱动后得到的迭代式加密核被改写为单输出槽起始实现。本任务模拟集成要求，需在同一模块中支持 FIPS 197 加解密、限制同一密钥的连续解密延迟，并在输出受阻时继续处理下一块。[FIPS 197](https://csrc.nist.gov/pubs/fips/197/final)

## 验收条件

| 条件 | 上限或行为 |
| --- | --- |
| 加密延迟 | 160 周期 |
| 新密钥解密延迟 | 190 周期 |
| 同一密钥连续解密的第二块 | 155 周期 |
| 映射资源 | 5,100 个通用单元，其中触发器最多 720 个 |
| 输出背压 | 保持第一块稳定，同时接受第二块 |
| 解除长背压 | 同一上升沿交付第一块并接受第三块，沿后立即呈现第二块 |
| 复位 | 同步低有效，撤销进行中请求和待交付结果 |

单元总数包含组合逻辑和触发器，触发器另有上限。一套完整的 11 轮密钥表就需要 1,408 位寄存器存储，参考解通过按需推导轮密钥控制占用。背压约束要求分离正在呈现的结果和正在计算的状态。

## 参考设计与对照

参考解每轮用 2 周期推导轮密钥、8 周期替换状态字节、1 周期移行和 4 周期处理列。加密和同钥解密各用 151 周期，换钥解密额外用 20 周期生成末轮密钥。它缓存末轮密钥及对应的输入密钥，解密时逆推每一轮的密钥。S-box 的正逆变换复用两路正向查表逻辑。已完成的第二块可暂存在工作寄存器，释放第一块的边沿同时转存结果和接收下一块。

| 实现 | 单元 | 触发器 | Reward | 主要结果 |
| --- | ---: | ---: | ---: | --- |
| 起始加密核 | 3,300 | 314 | 0 | 加密通过，解密和背压重叠失败 |
| 参考解 | 4,853 | 682 | 1 | 全部检查通过 |
| 每次重算末轮密钥 | 4,214 | 425 | 0 | 重复密钥解密超出 155 周期 |
| 输出阻塞时停止接收 | 4,853 | 682 | 0 | 无法接收第二块 |
| 正逆 S-box 分开查表 | 5,317 | 682 | 0 | 功能通过，超出单元预算 |

独立评分器用 Icarus Verilog 12.0 和 Yosys 0.33 检查 RTL 及综合网表。两者都要通过加密、解密、重复密钥、输出重叠、复位和混合流量六组测试。向量包括三组已知答案、OpenSSL 生成的不同密钥与数据，以及只差一位的密钥交替出现的场景。映射单元数是固定综合流程的资源代理指标。全部检查通过时 `reward.txt` 为 1。[Harbor 独立评分环境](https://docs.harborframework.com/tasks/separate-verifier)

完整反例位于 `authoring/evidence/controls/block-on-stall.sv`。该实现通过加解密、重复密钥、复位与混合流量检查，综合资源也合规。当第一块的输出持续被阻塞时，它无法接收第二块，RTL 和综合网表均在重叠测试中失败。逐项日志见同目录的 `block-on-stall-grade.json`。

### 失败模式

- **逻辑资源超限。** Terra 的三份提交都通过了两类仿真的六组功能检查，触发器也都在上限内。两份提交分别超出 427 和 201 个单元。满分提交用 5,059 个单元，距上限 41 个单元。
- **RTL 改动无法通过综合。** Flash 的两份改动在组合列运算中推断出锁存器，Yosys 综合失败。另一份提交保留起始 RTL，只通过加密组。
- **未实现有效改动。** Pro 的三次运行都在写入任何 RTL 改动前用尽 12,000 个输出 token，仅通过起始核的加密组。Qwen 有两次运行提交了起始 RTL，一次提交缺少完整的 `aes128` 模块。

评测汇总包含 12 次完成判分的正式运行。DeepSeek 的工具接入试跑暴露了文本工具调用和回复截断处理问题，修正后进行了正式运行。包内保留每次正式运行的配置、工具轨迹、提交文件和判分记录。
